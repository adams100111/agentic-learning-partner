# Negative Evidence

## Principle

A failure is not automatically evidence that a competency level should decrease.

## Classification

Before affecting competency, negative evidence should be assessed as one or more of:

- syntax miss;
- conceptual miss;
- implementation miss;
- tooling/ecosystem miss;
- careless/transient miss;
- ambiguous/bad task;
- environment/infrastructure failure.

## Effect

The assessment determines what the failure actually demonstrates.

Examples:

- a syntax typo should not downgrade architecture reasoning;
- a library API mistake may indicate ecosystem unfamiliarity rather than language weakness;
- repeated independent conceptual failures may justify downgrade or targeted reassessment.

## Repetition

Repeated high-quality contradictory evidence should matter more than one isolated failure.

The projection engine uses accepted assessments, not raw pass/fail counts.
